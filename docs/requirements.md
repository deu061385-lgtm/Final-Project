# Stride 기능 요구사항 정의서

## 1. 서비스 개요

- **서비스명:** Stride — 러너 AI 코치
- **문제:** 러닝과 축구·근력 운동 등 여러 활동을 병행하는 일반 사용자는 운동 이력, 회복 상태, 다음 운동 계획을 한곳에서 관리하고 개인 맥락에 맞는 조언을 얻기 어렵다.
- **목표:** 운동 기록과 사용자 컨텍스트를 관리하고, 생성형 AI가 안전한 운동 코칭과 일반적인 운동·영양 참고 정보를 제공한다.
- **대상 사용자:** 러닝을 중심으로 여러 운동을 기록하고, 운동 경험이 초급에서 중급인 일반 사용자.

| FR-10 | 화면에서 AI 생성 운동 가이드임을 사용자에게 알린다. | Must | 구현됨 |

| ID | 항목 | 요구사항 | 구현 또는 확인 방법 |

| NFR-02 | 개인정보 최소화 | 연령대·당일 컨디션은 계정에 저장하지 않고, AI 전송 전 동의를 확인한다. | 코치 요청 검증과 UI 동의 체크 |
| NFR-03 | 비밀정보 관리 | Codyssey API 키와 Supabase 비밀 키를 클라이언트·GitHub에 포함하지 않는다. | 서버 환경변수 사용. Supabase service role 키 미사용 |
| NFR-04 | 응답 검증 | AI의 JSON 필드, RPE 범위, 안전 수준을 검증하고 잘못된 응답은 사용자에게 표시하지 않는다. | 코치 API 응답 파서 |

| NFR-06 | 사용성 | 모바일 화면에서 기록·일정·코칭 기능을 이용할 수 있어야 한다. | 반응형 UI 및 실제 기기 테스트 필요 |

## 4. AI 기술 요소

- **Long-term Memory:** `coach_profiles`의 사용자 목표·운동 경험과 `activity_records`의 운동 이력을 계정별로 보관하고 다음 코칭에서 활용한다. 대화 이력 메모리는 구현하지 않았다.
- **AI Agent / 도구 사용:** 모델이 필요하다고 판단할 때 `get_recent_activities`를 요청한다. 서버는 도구 이름·인자를 검증하고 인증된 사용자의 기록만 조회한다. 이 구현이 과제 평가에서 AI Agent로 인정되는지는 평가자 확인이 필요하다.
- **RAG:** `src/lib/coach/fitness-knowledge.ts`의 운동·영양 요약과 검색 키워드를 질문과 대조하고, 관련 청크를 AI 입력에 넣는다. 응답에는 실제로 검색된 원문 출처 링크를 표시한다. 검색은 키워드 기반이며 외부 웹을 실시간 크롤링하지 않는다.

## 5. 안전·개인정보 원칙

- AI 생성 운동 가이드임을 화면에 표시한다.
- 코치 요청 전에 기록·컨텍스트를 Codyssey AI API로 보내는 데 대한 동의를 확인한다.
- AI는 진단·치료·개인별 식단 처방을 하지 않는다. 통증·위험 증상에는 보수적인 운동 안전 안내와 전문가 상담을 우선한다.
- 당일 컨디션과 연령대는 요청에만 사용하며 DB에 저장하지 않는다. AI 대화 내용도 저장하거나 후속 요청에 전달하지 않는다.

## 6. 검증 및 미완료 사항

- 최소 5명의 외부 실사용자 테스트와 피드백 반영 결과를 제출 전에 기록해야 한다. 완료 인원과 설문 결과는 실제 응답 시트로 확인 후 기입한다.
- 팀원별 역할과 실제 기여는 팀 합의 및 GitHub 이력을 근거로 별도 문서화해야 한다.
- Google OAuth, RLS가 적용된 실제 계정 흐름, Agent 도구 호출과 RAG 출처 표시를 팀 테스트 계정으로 확인하고 결과를 기록한다.
- 사진·동영상 자세 분석, 대화 이력 저장, 개인별 칼로리 계산, 상세 재활 처방은 현재 지원하지 않는다.
