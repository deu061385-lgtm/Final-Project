# Stride 프로젝트 기획서

## 1. 프로젝트 개요

- **서비스명:** Stride - 러닝·운동 기록과 AI 코칭 서비스
- **목표:** 여러 운동의 기록과 계획을 한곳에서 관리하고, 사용자 목표·운동 이력과 큐레이션 자료를 참고하는 AI 코칭을 제공한다.
- **배포 주소:** https://runner-ai-coach.vercel.app

## 2. 문제 정의와 대상 사용자

러닝과 축구·근력 운동 등 여러 활동을 병행하는 일반 사용자는 운동 이력, 회복 상태와 다음 활동 계획을 한곳에서 관리하기 어렵다. 기록을 보더라도 최근 운동량과 현재 컨디션을 함께 고려해 다음 운동을 결정하기 쉽지 않다.

Stride는 러닝을 중심으로 여러 활동을 기록하며, 초급에서 중급 수준의 운동 계획과 일반적인 코칭을 원하는 성인 사용자를 대상으로 한다. 의료 진단이나 재활 처방이 필요한 사용자를 위한 서비스는 아니다.

## 3. 해결 방식과 MVP 범위

- 러닝·축구·기타 활동의 시간과 RPE를 기록한다. 러닝은 거리도 기록한다.
- Google 로그인 사용자의 운동 기록, 코칭 목표·경험, 운동 계획을 계정별로 저장한다. 로그인 전 기록은 브라우저에 저장하고 사용자가 명시적으로 계정에 가져올 수 있다.
- 주간 일정에서 날짜별 운동 계획을 추가·조회·삭제한다.
- 사용자가 동의한 코칭 요청에 선택한 연령대와 당일 컨디션을 포함한다. 이 값과 대화 내용은 계정에 저장하지 않는다.
- AI가 필요하다고 판단하면 읽기 전용 도구로 로그인한 사용자 본인의 최근 운동 기록 최대 10건을 조회한다.
- 운동·영양 질문에 큐레이션 자료를 검색해 답변 근거로 제공하고, 실제 사용한 출처를 표시한다.
- AI는 안전을 고려한 일반 운동 코칭과 일반 영양 가이드를 제공한다.

### 범위에서 제외

대화 이력 저장 및 이어 묻기, 근력 운동의 세트·횟수·중량, 사진·동영상 자세 분석, 웨어러블 연동, 개인별 식단·칼로리 처방은 MVP에서 제외한다. 통증이나 위험 증상에 대해서는 진단·재활 루틴 대신 운동 중단과 전문가 상담을 우선한다.

## 4. AI 활용과 기술 요소

미션 필수 기술 요소 중 **Long-term Memory와 RAG**를 사용자별 데이터 저장 및 큐레이션 지식 검색으로 구현한다. AI Agent 도구 호출도 추가했으며, 과제 평가에서 Agent로 인정되는지는 평가자 확인이 필요하다.

| 기술 요소 | Stride 적용 방식 | 범위와 한계 |
| --- | --- | --- |
| Long-term Memory | Supabase에 계정별 운동 목표·경험과 운동 기록을 저장해 이후 코칭에 활용 | 대화 내용은 저장하지 않음 |
| RAG | 운동·영양 큐레이션 자료에서 질문 키워드와 일치하는 내용을 찾아 AI 입력에 추가하고 출처 표시 | 로컬 자료의 키워드 검색이며 실시간 웹 검색이나 임베딩·벡터 검색은 하지 않음 |
| AI Agent 도구 사용 | 모델이 필요하다고 판단하면 `get_recent_activities`를 호출하고 서버가 본인 기록 최대 10건을 읽어 반환 | 읽기 전용 단일 도구이며, 자율 다단계 계획이나 일정 변경은 하지 않음 |

## 5. 기술 스택과 선택 이유

아래 이유는 현재 구현의 요구와 운영 방식에 기반한 설명이다.

| 기술 | 선택 이유 |
| --- | --- |
| Next.js App Router, React, TypeScript | 화면과 서버 API를 한 프로젝트에서 구성하고, TypeScript strict 검사로 요청·응답 자료 구조를 명시하기 위해 선택 |
| Supabase Auth, Postgres, RLS | Google 로그인과 관계형 사용자 데이터를 함께 관리하고, 행 단위 정책으로 계정별 접근을 제한하기 위해 선택 |
| Codyssey OpenAI 호환 Chat Completions API | 서버에서 모델 요청과 도구 호출을 제어하고, API 키를 브라우저에 노출하지 않기 위해 선택 |
| Vercel | Next.js 앱을 외부에서 접근 가능한 서비스로 배포하고 프로덕션 환경 변수를 관리하기 위해 선택 |
| 일반 CSS | MVP 화면과 반응형 스타일을 별도 UI 프레임워크 없이 프로젝트 안에서 관리하기 위해 선택 |

## 6. 개인정보와 안전 설계

- AI 데이터 전송 전에 로그인과 사용자의 동의를 확인한다.
- 계정 데이터는 Supabase RLS 및 서버의 인증 사용자 필터로 분리한다.
- 연령대·당일 컨디션과 코치 대화 내용은 DB에 저장하지 않는다.
- AI 생성 운동 가이드임을 표시하며, 의료 진단·치료·개인별 영양 처방을 제공하지 않는다.
- 통증·위험 증상에는 보수적인 안내를 제공하고 필요한 경우 운동 중단과 전문가 상담을 권한다.

## 8. 검증 계획과 현재 미완료 사항

- 프로덕션 URL 접근, Vercel 배포 상태, 로그인 사용자 1명의 코칭·최근 기록 도구·RAG 출처를 수동 확인했다. 상세 결과는 [배포 검증 기록](deployment-verification.md)에 있다.
- 실제 사용자 최소 5명의 테스트 완료를 팀원 보고와 사용자 확인으로 확인했다. Google 응답 시트 최종 대조와 익명 피드백 집계가 남아 있다. 세부 내용은 [사용자 테스트 기록](user-testing.md)에 있다.
- 무관한 질문의 출처 미표시와 일정 기능의 외부 사용자 흐름은 추가 검증이 필요하다.
- 자동화된 통합·부하 테스트와 CI 검증은 현재 구성되어 있지 않다.
